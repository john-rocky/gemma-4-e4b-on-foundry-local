Speed measured again with High QoS, 2026-11-11, 09:33-11:30, Windows 11 build 26200.9711, on the same laptop and GPU
drivers as the published numbers. This file lists each timed process of the forms below.

Power settings during these runs: MSI Center's User Scenario on Balanced, Windows' power mode on its default (no
power mode overlay), on AC power. The published numbers of 2026-11-06 were measured with MSI Center's earlier
setting (not Extreme Performance; which setting it was is not recorded).

The packages: Hugging Face mlboydaisuke/gemma-4-E4B-it-Foundry-Local at 9d1751f, cuda-int4-8k/ for Foundry Local on
the RTX, cpu-int4/ for ONNX Runtime GenAI. Python: the versions of requirements-genai.txt.

How: every timed process was started by a PowerShell script that was itself started over ssh (Win32_Process.Create);
the sitting lines below give the desktop's state (LogonUI = Windows' lock-screen process). The published script runs
unchanged (runpy), with the published number's arguments.
High QoS = SetProcessInformation(ProcessPowerThrottling, ControlMask = EXECUTION_SPEED, StateMask = 0); default = no
call. State 1/0 = power throttling opted out (High QoS); 0/0 = nothing set.
ONNX Runtime GenAI: the process makes the call at its start, before the published script and its imports run. Each
process reads the state back at its start and at its end, and times a fixed 30,000-iteration Python loop at its
start and three times at its end (the end value below is the fastest of the three, with the core type it ran on).
Foundry Local: each timed row is a fresh daemon (foundry server stop, foundry server start). High QoS = the same call
on the daemon's process, made from another process by its process id, right after foundry server start and before
the model is loaded. fl_rest.py itself makes no call in either case. The daemon's state is read after the call and
after the speed run. Core sample: the busy % of every logical processor over 4 s, starting 12 s into the speed run;
a row gives the sum over logical processors 0-3 (the four P-cores) and the sum over 4-15.
Order: High, default, default, High. A row's value = the mean of its two processes of one QoS.
Controls: a static fp16 graph on the Intel GPU (Windows ML, OpenVINO EP, 101 tokens, default QoS), run before each
form and again after the form plus 180 s of idle. On this laptop it takes 98.2 ms (103.0 ms when its own load takes
35 s or more) or, in a faster state whose cause is not established, 92.8 ms (known only for a load under 35 s). A form
counts when each of its controls is within 5 % of one of these values for its load time, when its controls are within
5 % of each other if any of them is in the faster state, and when its two High processes are within 5 % of each other.
A control right after the last process is recorded only.
The closing control of a form is also the control before a form that follows it directly: the first two forms below
share the 95.0 ms control.
Forms not counted get one more run. OpenVINO on the Intel GPU ran twice: in the first run its two High processes came
19.4 % apart (8.18 and 6.85; default 5.83 and 5.84), so the block below is its second run. The CPU package on Foundry
Local's CPU EP ran twice and is not listed: in both runs the control between the two halves of that form, which
loaded in more than 35 s, was more than 5 % from the one value known for that load time (94.2 and 93.8 ms against
103.0 ms); in the first run its two High processes were also 7.3 % apart.
